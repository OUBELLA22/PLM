The basics

What an ECO is

  • ECO = Engineering Change Order — the PLM object that officialises a product change.
  • Equivalent of the FM (change sheet) in SAP / 3DCom.
  • It carries the change, not the geometry: approvals (RT / RAL), homologation, impacts, dates, notifications.
  • Type used here: ECO Type = Product (there are also Component ECOs).
  • No released product without an ECO — it is the gate to officialisation.
One sentence to remember: the ECO is the passport of a change.

Before you click

Prerequisites

  • Role: PSA_Pilote_Projet or PSA_Concepteur
  • Diversity and applicability contexts are defined
  • Expected Product (PA) created with diversity applicability
  • Reviewer and approval lists created and defined — RT and RAL templates must already exist.
  • The PDEF, PREA or DOC concerned exists
  • ECR in Design for a revision — or OA/LA in Create for a first release / reuse.
Missing one of these is the #1 reason a creation or a promotion fails.

Method 1 · shortcut

Create several ECOs in one go

  • Set Number of ECO to create before validating.
  • PLM opens a mass-update grid: same attributes, N ECO numbers.
  • Use Mass Update to change a column on every line, then Save.
  • Ideal when one change hits several parts of the same perimeter.

Impacts

V / O / M impacts & manufacturing site

  1. Check the Project Space attribute.
  2. Search the project name.
  3. Select the result whose type is Project Space, then Submit.
  4. Choose one or more manufacturing sites — they fill the Manufacturing Site field automatically.
The warning from the methodology
“No active manufacturing site in this project space” › the project space is not set up. Contact the Project Owner (RPP / RPCR); you cannot fix it from the ECO.

Impacts

Pick the project space, not the product line

  • Refine on Types › Project Management › Project Space.
  • Check the line whose Type column reads Project Space, then Submit.
  • Never select a Product Line (PL-000000) — impacts would be wrong.

Management

Put a due date on the approvals

  • Identity card or Categories › Lifecycle › tab Approvals › Edit.
  • Column = Due Date, Value = dd/MM/yy, pick the day in the calendar.
  • Tick the RT / RAL lines › Apply to Selected (or Apply to all) › Done.
  • Result: every RT and RAL task carries a visible deadline.

Colours

Neutral PDEF & Diversity Manager

  • Defining colours requires a “Neutral” PDEF.
  • The Diversity Manager must be informed › put his ID on the ECO:
  • ECO identity card › Actions › Edit Details › field Diversity Manager › search the ID › submit.
  • Forget it and the promotion fails — see the next slide.
No Diversity Manager ID = blocked system. Fill it at creation, not when the workflow stops.

The blocker

Promotion failed: Neutral products connected

  • A coloured product (COL-…) sits next to the PDEF under the PA.
  • The ECO shows Diversity Manager: Unassigned.
  • Promotion is refused: “There are Neutral products connected to the ECO, you must enter a Diversity Manager ID”.
  • Fix: Actions › Edit Details › set the Diversity Manager, then promote again.

Tips

What experienced users do

  • Create from the product (UC 2) to avoid an orphan ECO.
  • Batch-create when several parts share one change.
  • Call the Homologation Manager first — some breakdowns are exempt from RHN flows; the approver holds the list.
  • Fill Notification's context on any JV / partner ECO, or the folder is never diffused.
  • Set the Diversity Manager as soon as colours are involved.
  • Fill every black field early — the window closes after Define Components.
  • Put due dates on RT and RAL — no date, no follow-up.
  • Check the ECR is in Design before hunting for the Create Product ECO action.

Wrap-up

Remember 5 things

01The ECO is the gate: no ECO, no released product.
02Prerequisites first — role, ECR in Design, RT/RAL templates.
03Red fields to create, black fields before Define Components ends.
04V/O/M = Project Space, never the Product Line.
05Colours involved › Diversity Manager ID, or the system blocks.
